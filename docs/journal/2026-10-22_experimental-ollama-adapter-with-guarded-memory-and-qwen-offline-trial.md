# Experimental Ollama adapter with guarded memory and Qwen offline trial

## Context and decisions

Following the committed Codex Electron adapter at d47ca3a on feat/codex-electron-adapter, the user requested trying Qwen, configurable multimodal models, hardware-based suggestions, proper journal use and consideration of automatic compaction. Implemented an experimental Local Ollama provider through the existing Codex app-server harness. This supersedes the implementation status in the earlier feasibility research entry; the research remains historical. New work is uncommitted and nothing was pushed.

Inference remains entirely in the external agent CLI. Application HTTP access is limited to bounded, loopback-only Ollama metadata (tags/show/ps), with no hosted fallback. Campaign state and notes remain CampaignStore transactions and typed reducers. Raw journal tools are not exposed to the shipped agent.

## Completed changes

- src/desktop/local.ts and contracts.ts implement arbitrary installed model names, vision plus tools requirements, cloud-model rejection, context/capability checks, hardware estimates, Qwen size suggestions, and actual runner context verification. NVIDIA VRAM and Apple unified memory inform conservative recommendations; download size is not a runtime fit guarantee.
- desktop setup/IPC supports provider, endpoint, model and context settings. Local mode has isolated Codex home, model catalog and session identity; switching model/context/endpoint loads campaign memory into a distinct conversation. The original plugin and Antigravity paths retain their behavior.
- src/desktop/memory.ts and desktop/server.ts require DM resume, history search and an exact record read when references exist before writes; publication also requires a continuity record after the latest mechanics. Retry operation IDs still reach normal transaction validation. Guards enforce steps, not factual accuracy or relevance.
- src/desktop/codex.ts configures local native compaction at 70% of the budget, a compact summary prompt, bounded active-request continuation through turn/steer, and explicit compaction completion handling. Failed handoffs stop without replay. Eight consecutive failed campaign calls stop local turns; successful calls reset the budget. Local prompts bound table excerpts, omit unavailable artwork instructions and reject oversized submissions before saving them.
- Added a generated Codex model catalog with image modalities. Live investigation showed Codex also drops accompanying MCP PNG blocks when preferring structuredContent; local image results now send identical JSON as text beside the image. Default plugin results remain unchanged. Native artwork generation is unavailable locally; existing registered art and schematic rendering are supported.
- Added test/local.test.mjs, test/integration/local.mjs and protocol/UI coverage, plus setup, limitations and verification documentation in docs/desktop.md, docs/architecture.md and docs/verification.md.

## Verification actually run

108 automated tests pass. Typecheck, isolated real journal integration, Electron UI smoke, LAN browser smoke, formatting and plugin packaging pass. Hosted Codex/Antigravity live scenarios were not rerun for this increment; their prior milestone evidence remains in the earlier entry. Existing shared journal daemons were not stopped or reconfigured.

Installed portable Ollama 0.40.8 and qwen3.5:9b Q4_K_M outside the source repository. Codex CLI is 0.162.1. On the 16 GiB RTX 5060 Ti / roughly 60 GiB RAM development machine, Ollama reported a 65,536-token runner entirely on GPU with about 7.7 GB allocated to the model (other GPU usage is additional). Model artifacts were downloaded before offline testing.

Untuned Qwen probes demonstrated saved recall and some successful damage/publication, but repeated 32k stress runs failed through malformed arguments, omitted effects or compaction loops. A 64k untuned run also repeated malformed mutation calls and was stopped after roughly 148 seconds. Automatic compaction occurred in the failing 32k runs; those are not successful gameplay-continuation results. An isolated image diagnostic correctly identified red with content-only PNG, whereas the structuredContent variant omitted the image and hallucinated a color; this motivated the scoped transport fix.

A separate local model alias dm-qwen3.5:9b (FROM qwen3.5:9b; num_ctx 65536; temperature 0.2) passed the complete synthetic scenario in about 252 seconds inside a private Linux network namespace with only loopback. The original model tag was unchanged. It verified saved boat/password recall, exactly two damage, duplicate submission protection, magenta image interpretation, explicit native compaction, fresh-process resume with correct password/HP, and private-sentinel exclusion from public snapshots. Player turns were approximately 94, 30, 28 and 34 seconds. The short successful 64k run had zero automatic compactions; its one compaction was explicit. This single pass does not establish causality for the temperature change or long-session reliability. Journal integration deliberately used keyword fallback, not semantic embeddings. All test campaign and runtime artifacts are outside the source checkout; the test-owned servers/daemons are cleaned up.

## Limitations and next steps

Local mode is experimental in the UI/docs. Any installed vision/tool model can be selected, but metadata capability claims do not certify correct tool choice, rules adjudication, narration or secret handling. Full local image generation and independent referee quality remain unsupported or unverified. Automatic compaction has protocol coverage and live triggering evidence; a successful long-running gameplay stress evaluation through automatic compaction remains outstanding. Before relying on local mode for a campaign, repeat the fixed synthetic scenario and evaluate a longer session with intended rules/review settings, including automatic compaction, recovery and relevant journal reads. Consider a stronger model or smaller, focused tool schemas if Qwen 9B continues to make malformed calls. Do not weaken reducers, operation IDs or memory guards to make a benchmark pass.

The runtime/model and tuned alias are installed locally; start Ollama with cloud disabled and a 64k context, launch npm run desktop, and choose Local Ollama with dm-qwen3.5:9b to reproduce the passing configuration. Reproduction commands and the Modelfile are documented in docs/desktop.md. No service was installed or existing daemon reconfigured. Review the source and journal changes before committing; this increment has not been committed or pushed.
